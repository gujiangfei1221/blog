# 1.痛点
在自己手搓了精简版openclaw后，我们会面临1个问题，我们能拿它来干嘛？

这边我有一个痛点：我每天会产生很多想法，工作上也需要处理很多任务，将这些东西归归类，其实归纳为：备忘类事情、任务类事情，其中任务类事情我选择了滴答清单作为统一入口进行管理（降低认知负担）

但是有时候在通勤路上或者不方便打开电脑的时候，我喜欢打开微信，对文件传输助手发送相关信息，事后再整理到滴答清单，但这往往意味着，很多想法丢进文件传输助手的‘黑洞’后，就再也没有然后了

这时候我在想，为啥不让weclaw直接帮我记录到滴答清单呢？结合AI的能力，它还能帮我进行分析、排期、提醒等，非常像我的私人日程管家了！

# 2.分析
在做之前，我们得先思考下这个场景的价值，也就是通过weclaw对接滴答清单，能帮我解决什么问题？为什么我不直接打开手机端滴答清单？为什么我喜欢通过微信文件助手来记录呢？

这边我思考和总结了为什么我偏爱微信文件助手：
1. **工具定位**：滴答清单是专业的任务管理软件，它有很多丰富的功能，但是在我产生灵感的时候，我并不希望按照它的流程来（找到对应文件夹->记录->标记预期完成时间->打标签），我希望的是快速记录，后续再整理
2. **启动成本**：微信作为国民级软件，我的电脑、手机都是一直开着的，想要快速记录灵感、备忘，微信非常的方便，而滴答清单我大概率是关闭的，启动超过3秒就会让我产生放弃打开的想法

那weclaw对接滴答清单，我原来的习惯还是得以保留，不过是我发送的对象从微信文件助手变为了我的订阅号，另外weclaw可以直接同步录入数据到滴答清单，省却了我后续整理的工作，**很适合我的日常习惯**！

# 3.解决
在分析了我的痛点场景，明确了场景价值后，接下来就是开搞！

如何让weclaw实现操控滴答清单，其实很简单，写1个skill就行，通过对接滴答清单官方的文档，调用它提供的增删改查接口即可，这个具体过程就不详述了，对应的skill可以直接看我的github：https://github.com/gujiangfei1221/WeClaw

# 4.思考
1、回到最开始的问题：部署了weclaw（openclaw），**我们需要它干嘛**？这其实是最关键的问题，**想好自己的场景，并通过价值论证**，证明AI工具的确能产生价值！

2、工具应该是服务于人的：过去我们要学着去适应软件的逻辑（填表单、点按钮），但现在，AI 应该来适应我们（听懂大白话，去干脏活累活）。
